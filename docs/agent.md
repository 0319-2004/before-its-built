# エージェント化（`pipeline/agent.py`）の手順と実測

方針は `docs/dev-policy.md` §3。ここは**動かし方と、撮った8枚で実際に出た結果**。

## 動かす

```bash
source .venv/bin/activate
python pipeline/agent.py data/photos/2026-11-01/IMG_3928.JPG   # 1枚
python pipeline/agent.py --all data/photos/2026-11-01          # まとめて
```

判断の記録は `data/agent/<写真の名前>.json`（リポジトリに入れない）。
1手ずつ、呼んだツール・入力・結果・モデルの短い理由・かかった時間が入る。

`process.py` との違いは**順番を誰が決めるか**だけ。部品は同じものを呼んでいる。

### 確かめた4つの例

**IMG_3928（住居表示の1番/17番）** — 住居表示を`address`として分けて取るようにした後は
看板から正しく「3丁目17番」と読めている。エージェントは住居表示ではなく**地番で**届出を
引いたので、仮に住居表示を読み間違えても照合できる経路になっている。

**IMG_3936（敷地面積 71.87 / 70.32）** — `lookup_filing`が不一致を返し、エージェントは
`reread_fields(["site_area_m2"])`で敷地面積だけを`medium`で読み直した。
値は71.87のまま変わらず（確信度は0.9→0.95）。読み間違いではなく看板と届出で実際に
数字が違う例なので、**どちらかに決めず**`mismatch_notified`で終わり、
`unresolved`に食い違いを残した。3Dは残りの項目で立てている。これが期待する振る舞い。

**IMG_3922 / IMG_3933（対象外の看板）** — `notice_type`が`other`になった時点で
ほかの項目を読まずに`request_retake`。IMG_3933 は看板が2枚写っていたので、
エージェントが`read_board(board=1)`で2枚目も確かめてから撮り直しを頼んだ。

**IMG_3966（届出なし・矛盾が残る）** — 地番814-1・814-2と名称で引いても届出は0件
（延べ2万㎡超で区の中高層リストに載っていない）。高さの欄が潰れていて、
9階に対して11.985mと読めるため「1階あたり1.3m」で検算に引っかかり、
読み直しても解消しなかった。**建物は立てずに終わる。**

この1枚は実行ごとに`needs_review`と`needs_retake`のどちらにもなる。
高さが本当に読めない写真なので、「届出がないから要確認」と見るか
「高さが読めないから撮り直し」と見るかはモデルの判断が割れる。
どちらでも**建物を立てない**ところは安定している。

## この回で見つけて直したこと

**モデルが階数から高さの桁を補っていた。** 最初の実行で IMG_3966 の高さを`31.985m`
（確信度0.6、注記に「画像が不鮮明で先頭数字が潰れ気味だが9階建てのため31.985mと判断」）
と返した。9階なら1階3.55mで**検算は通ってしまう**ため、そのままなら42m近い建物が
立っていた。直したのは2つ:

1. 読み取りの指示に「ほかの欄から逆算して数字を埋めてはいけない」を足した
   （`read_board.py` の `PROMPT`）。次の実行からは`unreadable`（確信度0.3）と正直に返し、
   読み直して11.985m、検算が矛盾を捕まえるようになった
2. `extrude()`が、高さ・建築面積の確信度が`0.9`未満なら立てないようにした
   （`read_board.low_confidence_fields()`）。検算を通る値でも止まる

**モデルの壊れたJSONが「写真が悪い」に化けていた。** IMG_3922 で
`{"fields": {"notice_type": {…}}` と**閉じ括弧を1つ落とした**JSONが返り（再現する）、
`json.loads`が投げた`JSONDecodeError`を見たエージェントが
「看板の読み取りに失敗しました。正面から明るく撮り直してください」と結論していた。
`read_board.parse_json()`が閉じ括弧だけを補って読み直すようにし、
エージェントには「ツールのエラーを写真の問題だと決めつけない」を指示に足した。

**`LOW_CONFIDENCE`が2か所にあった。** `evaluate.py`が自分で`0.9`を持っていたので、
`read_board.py`を正本にして読み込む側に変えた。読み取り側と評価側で境目がずれると、
「自信なしの項目ほど間違っているか」が測れない。

## まだやっていない

- 評価（`evaluate.py`）は`process.py`の出力を見ているので、**エージェントの結果では
  まだ測っていない**。逆算禁止を足して読み取りの指示が変わったので、
  `docs/eval-summary.md` の数字は取り直しが必要
- `lookup_filing`の鍵に住居表示の「号」を使えていない（届出側に号の列がない）
- 解体の看板（`notice_type`が`demolition`）はツールに通していない
