## 食い違った項目の読み直し

検算や届出との食い違いで引っかかった項目だけを、推論の強さ`medium`で読み直した結果（dev-policy §3）。エージェントの `reread_fields` の手から数える。

- 読み直した写真: 7枚
- 値が変わった: 0件（読み直しても値は作らない。桁を補うのを防ぐため）
- 読み直しても検算の矛盾が残った: 2件（この場合は建物を立てない。IMG_3966 の高さ）

## 分かっている読み間違いの例

- IMG_3928（届出No.51）の住居表示：看板には「3丁目17番」と書いてあるが、地名地番と同じ欄に併記されていたため最初は「3丁目1番」と読んだ（写真で確認済み）。住居表示を`address`として分けて取るようにして直った。地番で届出を引いても17番と分かり、建物名「上目黒317」とも合う。
- IMG_3931・IMG_3936の高さ：軒高を`height_m`に入れていた（看板の書式が「高さ ○m（塔屋等まで ○m、軒高 ○m）」）。高さを3つに分け、検算に「軒高 ≤ 高さ ≤ 最高の高さ」を足して直った。3D表示は最高の高さ（なければ高さ）を使うので、軒高が高さの箱に入ったままだと建物が2m低く立っていた。

## まだ決着していない不一致

- IMG_3936（届出No.67）の敷地面積：看板の読み取りは71.87㎡、届出の読み取りは70.32㎡。届出のスキャンを目視して70.32㎡で確定（2026-11-01）。看板の写真の側は未確認なので、どちらの読み間違いかはまだ決まっていない。

## 比べ方

- 照合はエージェントが済ませている（地番 → 住居表示 → 建築物の名称 の順に試す）。ここでは記録の `filing_no` の届出と項目ごとに比べる
- 数値は小数点以下の書き方の違いを許す（`385.6` と `385.60` は一致）
- 文字は `pipeline/normalize.py` で表記をそろえてから比べる（丁目は漢数字、「ヶ」「ケ」、全角と半角、空白）
- 構造は 木造 / S造 / RC造 / SRC造 / その他 の5つにそろえてから比べる
- 日付は年月までしか読めなかった場合、年月が合っていれば一致とみなす
- 高さは3つ（高さ・塔屋等まで・軒高）を別々に比べ、3Dに使う数字が合っているかは「3D表示に使う高さ」（最高の高さがあればそれ、なければ高さ）で別に見る
- 「自信なし」は確信度 < 0.9、または状態が `unreadable`・`masked` の項目
- `mismatch_notified` で終えた写真の不一致は「実際の食い違い」として別に数える
- 複数の看板がそろって一致し、届出側の読み取りの誤りが疑われるものは「届出の誤り(疑)」として別に数える（看板の読み間違いにも実際の食い違いにも入れない）。目視確認で確定するまでは暫定
